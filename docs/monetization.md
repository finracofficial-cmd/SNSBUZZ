# 愛されポンコツ診断 マネタイズ計画

調査の詳細と出典は `research_notes/v2_benchmarks/monetization.md`（v2）と `research_notes/v3/paywall_patterns.md`（v3のチラ見せ・決済・法規制）にある。このメモはその結論と、実装した内容、次にやることをまとめたもの。数字のうち実測でないものには「推定」と書いている。

月100万円に向けた売上の式・シナリオ・運用は `docs/revenue-plan.md` にまとめた。

## 前提

- 利用者の中心は10代後半〜20代前半の女性で、スマホから使う。流入元はTikTok・Instagram・X。
- 10代のお小遣いは、中学生で月約3,300円、高校生で月5,400〜6,400円。推し活への支出は月約6,000円（調査メモ1-5）。
- 10代はクレジットカードを持っていないことが多い。使える決済は、PayPay・キャリア決済・プリペイドが中心になる（調査メモ2章）。
- 診断サイトのPVは、バズで一気に増えて、その後急に落ちる。ラッコ案件（悪口診断とみられる）は、自社SNSを止めてから3か月でPVが約95%減った。月平均ではなく、**バズ1回でいくら残せるか**で設計する。

## 実装した「完全版」（v3）

### 無料と有料の分け方

v3では、診断を**かんたん診断（12問・全部無料）**と**くわしい診断（＋24問）**に分けた。くわしい診断のレポート（全8章）は、ふんわりした部分を無料で見せて、くわしい部分にモザイクをかけている。

| 無料 | 完全版（モザイクが外れる） |
|---|---|
| かんたん診断の結果とタイプ解説（全部） | — |
| 二つ名・恋愛タイプ名・10項目のランク（S〜D）・4軸の％・必殺技と弱点 | 6パラメータの％ |
| 6パラメータの段階（高め・ふつう・低め）と冒頭の一言 | 6パラメータのくわしい解説 |
| **二つ名のもとになったパラメータの解説の前半（見本）** | その後半 |
| 恋愛タイプのキャッチと冒頭の一言・相性のいい恋愛タイプの名前 | 恋愛タイプの深掘り・恋のアドバイス3つ・相性の理由 |
| 第4章の1文目（予告）と、第4〜8章の見出し | 本当のあなた／ポンコツを武器にする3つの方法／恋愛の落とし穴と攻略法／2027年の過ごし方ヒント／ひとことエール |
| 二つ名カード・プロフ帳カード・6枚のカルーセル | ステータスカード・金色の枠の結果カード・**ロック画面の壁紙**（1170×2532。時計と通知に重ならない配置） |

- 有料の文章は、1タイプあたり約1,200〜1,450字。パラメータと恋愛タイプを足すと、1人あたり約2,500字になる。
- この分け方は、調査（`research_notes/v3/paywall_patterns.md`）の「チラ見せ」の型に合わせた。
  - 自分についての何かが「ある」ことを確かに示す（章タイトル・段階・ぼかした実体）。
  - 量を示す（「のこり7章・約2,500字」「約180字」）。
  - 価格と買い切りであることを先に出す（「390円・税込・買い切り・自動更新なし」）。
  - 見本で質を確かめてもらう（第1章の見本）。
- モザイクの下には本物の文章を置かない。同じ文字数のダミー文字をぼかして、購入後に出る量と一致させている。
- 無料の範囲は、ホーム・かんたん診断の結果・タイプページで「診断は無料。数値とくわしい解説は完全版（有料）」と、同じ場所に書いている（景品表示法の「無料」表示の考え方）。
- 購入率を見ながら、無料の量を15%・30%・45%で試すのが次の一手（調査メモ6-9）。

### 価格とプラン

| プラン | 価格 | 中身 | 設定 |
|---|---|---|---|
| じぶん用 | **390円**（税込・買い切り） | 全20タイプ分の完全版 | `STRIPE_PRICE_ID`（必須）・`PREMIUM_PRICE` |
| ふたり用 | 590円（税込・買い切り） | じぶん用＋友達1人が受け取れるプレゼント | `STRIPE_PRICE_ID_DUO`・`PREMIUM_PRICE_DUO`（設定したときだけ出る） |

- 390円は、10代が推し活のついでに払える額にそろえた。
  - 有料の相場は、ラブタイプ診断の個人鑑定980円、16TEST+の1,100円、16Personalitiesの29ドル。
- 「通常価格〇〇円→390円」のような二重価格は使わない（景品表示法）。
- 画面に出す価格（`PREMIUM_PRICE`）と Stripe に登録した価格がちがうときは、決済を始めない（`/api/checkout` が Stripe の価格を確かめる）。表示と請求額のずれを防ぐ。
- ふたり用は「友達と相性をくらべる」遊び方とつながる。プレゼントは最初に開いた1人だけが受け取れる。

### 購入の流れ

1. **購入案内**
   - 入口: 画面下の固定バー、第1章の直後のボタン、モザイクのタップ。
   - 第2章が見えたところで、**1回だけ**自動で出す。2回目からは、ボタンを押したときだけ。
   - LINE などのアプリ内ブラウザでは、「Safari や Chrome で開いてから購入するのがおすすめ」と出す（購入情報がアプリの中に保存されるため）。
2. **自社の最終確認画面**（特定商取引法12条の6）
   - 商品と分量・価格・支払方法・支払時期・提供時期・申込期間・キャンセルの各項目を表示する。支払方法は、実際に有効にしたものだけを書く。
   - **年齢の確認（必須）**:「18歳以上です」か「18歳未満で、保護者の同意を得ています」のどちらかを選ばないと進めない。
   - 確認のチェックボックスと、「次の画面（Stripe）でお支払いを確定すると、購入が完了します」の表示がある。
   - ボタンは「お支払い画面へ進む（390円・税込）」。
3. **Stripe Checkout**
   - 支払い方法は、既定ではカード（Apple Pay・Google Pay をふくむ）だけ。`STRIPE_PAYMENT_METHODS=card,paypay` で PayPay も足せる（Stripe の審査とダッシュボードでの有効化が必要）。コンビニ・振込のような後払いは使わない。
   - 最後の画面にも、返品不可（18歳未満は保護者の申し出で全額返金）と、すぐ読めることを出す。
   - やめたときは、読んでいた画面に戻る。
4. **`/thanks/` に戻る**
   - `/api/unlock` が支払いを確かめて、購入トークンを渡す。
   - 受け取れたら、決済のIDが入ったURLを消して、元の画面に戻る。引き継ぎリンクと、ふたり用ならプレゼントのリンクを出す。
   - 受け取れなかったら（通信が切れたなど）、その場で「もう一度確かめる」を出す。閉じてしまっても、次にサイトを開いたときに自動で確かめる（24時間まで）。
5. **Webhook**（`/api/stripe-webhook`）
   - ブラウザが戻ってこなくても、Stripe からの通知で購入を記録し、おうちの人の支払いなら子どもの端末への受け取りを用意する。
   - 返金されたら、その購入（とプレゼントを受け取った人）では読めなくなる。

### おうちの人に払ってもらう

10代はクレジットカードを持っていないことが多い（高校生のQR決済の利用は50.8%で、残高は親からの送金が多い）。そこで、親のスマホで払ってもらう流れを用意した。

1. 子どもが「おうちの人に払ってもらう」を押すと、子どもの端末が秘密の文字列を作り、そのハッシュ（受け取りID・16文字）入りのリンク `#/buy/<受け取りID>` ができる。LINEなどで親に送る。
2. 親が開くページには、商品の中身・価格・「エンタメ診断で、占いではありません」の説明だけを出す。子どもの診断結果や回答は見せない。
3. 親が払うと、Stripe の `client_reference_id` に入れた受け取りIDで、サーバー（D1の `claims`）に購入トークンを置く。
4. 子どもの端末は、開いている間だけ `/api/claim` を5秒ごとに確かめる。送るのは秘密の文字列なので、**リンクが転送されても、ほかの人は受け取れない**。トークンが届いたら、自動で完全版が開く。
   - 受け取りIDは7日で使えなくなる（子どもの端末でも、サーバーでも）。
5. 親の画面にも、引き継ぎリンクを出す（子どもの端末が自動で開かなかったときのため）。

### 端末の引き継ぎ・復元・コード

- アカウント登録はなし。購入トークンは端末のブラウザに保存する。
- **ブラウザのデータが消えたとき**: トークンは HttpOnly の Cookie にも入れている。iOS Safari はスクリプトが書いた保存データを7日で消すことがあるが、Cookie から自動で戻す（`/api/restore`）。
- **別の端末で読むとき**: 購入後に出る**引き継ぎリンク**（`#/unlock/<トークン>`）を開く。または「コード・引き継ぎリンクで開く」に貼る。
- **それでも読めないとき**: 購入者がメールアドレスを添えて問い合わせる。運営は Stripe のダッシュボードで支払いを確かめ、`PREMIUM_SECRET=… node scripts/issue-token.mjs cs_live_… https://ドメイン` で引き継ぎリンクを作って送る。
- **キャンペーン・タイアップのコード**（`PROMO_CODES`）
  - `OSHI2027:2027-03-31` のように期限をつけられる。期限を過ぎるか、コードを消すと、そのコードで開いた人も読めなくなる。
  - B2Bの「参加者全員に完全版をプレゼント」にそのまま使える。

### 仕組み

| 項目 | 実装 |
|---|---|
| 有料の文章の置き場所 | サーバー（`functions/_lib/premium.js`）だけ。ブラウザに配るファイルには、文字数と、第1章の見本（前半）・第4章の予告（1文目）しか入れない |
| 本文の返し方 | 購入トークン（ヘッダか Cookie）を持つ人にだけ、`/api/premium?i=タイプ&p=パラメータ` で返す。その人のパラメータの段階に合った解説を選んで返す |
| トークン | `v1.<ID>.<署名>`。HMACで署名し、偽造したトークンは弾く。IDの種類は、買った人（`cs_…`）・プレゼントを受け取った人（`gr-cs_…`）・プレゼント券（`gift-cs_…`。それだけでは読めない）・コード（`promo-…`） |
| 購入の記録 | D1 の `purchases`。返金済みかどうか、プレゼントが受け取られたかを持つ。支払い完了の数は、新しく記録したときだけ数える |
| 特定商取引法に基づく表記 | `#/legal`。販売事業者名などは `site/assets/config.js` の `seller` を埋める。価格と支払方法はサーバーの設定から表示する。本番ドメインを入れたのに `seller` が仮のままなら、ビルドが止まる |

### 決済まわりの注意

- **Stripe Japanは「占い」が禁止業種**（Psychic services and fortune tellers）。コンビニ決済はさらに、「非科学的・迷信に基づくコンテンツ」も対象になる。
  - そのため、完全版は「エンタメの心理テスト・自己分析」として作った。星座・運勢・「相性占い」の言葉は使っていない。
  - 「2027年のあなた」は「2027年の過ごし方ヒント」に変えた。中身も予言ではなく、行動の提案として書いている。
  - 相性のランク名も「運命の相方」から「最強の相方」に変えた。
  - `scripts/validate-content.mjs` で、占いの語（占い・鑑定・運勢・守護霊など）と予言の語（「〜するでしょう」など）を検査している。
  - 販売の前に、**Stripe（またはKOMOJU）に業種審査が通るかを問い合わせる**。
- **やらないこと**（消費者庁のダークパターン類型）
  - 「無料」とだけ書いて、有料の部分を後から見せること
  - 偽のカウントダウン
  - 「残りわずか」
  - 自動生成の購入者数
  - 購入案内を何度も自動で出すこと
  - 罪悪感をあおる文言
- **手数料**: Stripeのカードは3.6%。PayPayは、デジタルコンテンツ事業者だと9.48%。
- **キャリア決済**: Stripeでは使えない。10代に一番届くのはKOMOJU経由のキャリア決済（6.6%〜）なので、販売が伸びたら第2の決済手段として検討する。
- **未成年の購入**
  - 民法では、お小遣いの範囲の少額なら取り消しにくい。ただし、「成年ですか？」に「はい」を押させるだけでは守られない。
  - 購入の確認画面で、年齢（18歳以上か、18歳未満で保護者の同意があるか）を必ず選んでもらう。
  - 保護者から申し出があれば全額返金する運用にして、特定商取引法の表記にも書いた。返金すると Webhook でその購入のトークンが無効になる。
  - 「おうちの人に払ってもらう」流れは、同意を得たことを明確にする役目もある。

### A/Bテスト（v4）

調査（`research_notes/v3/paywall_patterns.md` 6-9）の優先順位にそって、端末ごとに案を固定して試す。定義は `site/assets/experiments.js`（サーバーにも同じものがある）。

| 実験 | 案 | 見るもの |
|---|---|---|
| `paybar` | `amount`（のこり7章・約〇字）／`specific`（「本当のあなた」と恋愛の攻略法を読む） | 決済へ進んだ率・支払い率 |
| `autopay` | `on`（第2章で1回だけ自動で購入案内）／`off` | 同上。押しつけ感とのかねあい |

- 表示・購入案内・決済へは端末ごとに1回だけ数え、支払い完了は Stripe に渡した目印でサーバーが数える。
- `#/admin` で案ごとの数字と、差があるかの目安（2つの割合の z 検定）を見る。購入率1〜2%の差を見分けるには、各案で数千人の表示が必要。判定は各案5,000人に達してから1回だけ（画面もそれまで p 値を出さない）。
- おうちの人の支払いも、お願いのリンクに入れた子どもの端末の案で数える。
- いま動いている実験：`paybar`（バーの文言）・`autopay`（自動の購入案内）・`calc`（結果の直前の「計算中」）。
- 決めたら負けた案を消し、次の実験（無料の量 15/30/45%、プランの数 など）に入れかえる。

### 価格テスト（月100万円の施策）

- `STRIPE_PRICE_ID_ALT` と `PREMIUM_PRICE_ALT`（例 490）を入れると、じぶん用の価格を**週ごと**（日本時間の月曜0時で切りかえ）に、いつもの価格と交互にする。
- 人ごとではなく週ごとにしたのは、同じ週ならだれが見ても同じ価格にするため（友達どうしで値段がちがう、が起きない）。特定商取引法の表記にも、週ごとに変わることがあると出す。
- 決済は「画面に出ていた価格」で作る。週が切りかわった直後の2時間は、前の週の価格の画面からでも、その価格で買える。それより古い画面からは 409 を返し、開き直してもらう。
- 支払い完了と売上は、実際に売った価格の案（`price:base`／`price:alt`）で数える。価格が上がると支払い率は下がるので、判定は**表示1回あたりの売上**の差で見る（`#/admin`）。最低4週（各案2週）続ける。

### 決済をやめた人へ（月100万円の施策）

- Stripe の画面で「戻る」を押した人（ブラウザの「戻る」で帰ってきた人も）に、**1回だけ**「どこで迷いましたか？」を出す。3日に1回まで。
- 選んだ理由に合わせて答える：高い（買い切り・1章あたり・ふたり用の割り勘）／払い方（使える払い方・おうちの人の支払い）／おうちの人に聞きたい（お願いのリンク）／中身（読めることの一覧）／いまはいい（結果は残っている）。
- 割引はしない（やめると安くなると覚えられると、買う人までやめるようになる）。理由は `left:*` で数え、次に直すところを決めるのに使う。

### ふたりの相性・完全版（月100万円の施策）

- 相性のページ（`#/pair/…`）に、4つの軸で見るふたり・けんかになりやすい場面と仲直りのコツ・似たもの同士の落とし穴・ふたりの最強の遊び方・ふたりへのひとことを足した。無料では見出しと、文字数どおりのモザイクだけを見せる。
- 本文はサーバー（`/api/premium/pair`）だけが持つ。完全版を持っていれば、だれとの相性でも読める（新しく買うものは増やしていない）。

### 紹介ループ（月100万円の施策）

- 結果のシェアと相性のおさそいのリンクに、端末のランダムな番号（`r`）を入れる。そのリンクから来た人が、その端末で**初めて**診断を終えたら1人と数える（`/api/ref`。同じ友達は1回だけ）。
- 3人で、虹色の枠の結果カードを保存できる。ごほうびは見た目だけで、完全版の中身は開かない。

### 次の収益の候補（v4の調査から）

- **コンビニのネットワークプリントのシール**：シール帳ブーム（10代女子のトレンド1位）と相性がよく、カードがなくても買える。プリント販売の事業者（L判250円前後・収益を分ける型）との契約が必要。
  - 段階1（入れた）：結果ページの「シール帳用のシール」で、L判のシール画像を無料で作れる。利用者がコンビニのシール紙で印刷する。QR から来た人は `ref:print` で数える。
  - 段階2（公開後）：`share:sticker` と `ref:print` が十分に出たら、タイプ別×季節の絵柄（1人ずつの名前は入らない）を、事業者のコンテンツプリントで売る。
- **プロフ帳の印刷版**：卒業・新学期に合わせて、QRつきで配る。

## 広告の置き方

- 結果の前の全画面広告は入れない（悪口診断がやっているが、シェアの直前に体験を壊す）。
- 結果ボタン・シェアボタン・選択肢の近くには置かない（誤クリックを誘う配置はAdSenseのポリシー違反）。
- 置く場所は、結果ページの「学校・バイト」と「トリセツ」の間、図鑑の下、タイプページの末尾。
- オファーウォールは、おまけ（例：「推しを当てはめるなら」診断、壁紙）の解放だけに使う。完全版と同じものを広告で開けられるようにはしない。

## 次にやること

1. **業種審査の確認**: Stripe（とKOMOJU）に、性格診断の有料レポートが審査に通るか問い合わせる。
2. **環境変数を設定して公開する**
   - `STRIPE_SECRET_KEY`、`STRIPE_PRICE_ID`（390円の価格ID）、`PREMIUM_SECRET`（長いランダム文字列）を設定すると、販売が始まる。
   - ふたり用も売るなら `STRIPE_PRICE_ID_DUO`（590円の価格ID）を足す。
   - Stripe のダッシュボードで Webhook（`/api/stripe-webhook`。`checkout.session.completed`・`checkout.session.async_payment_succeeded`・`charge.refunded`）を作り、署名シークレットを `STRIPE_WEBHOOK_SECRET` に入れる。
3. **購入率を測る**: 公開から2週間、`/api/stats?all=1` で次の数を比べる。

   | 段階 | キー |
   |---|---|
   | くわしい診断の完了 | `detail:done` |
   | 購入案内の表示 | `paywall:view`・`paywall:cta` |
   | おうちの人へのお願い | `paywall:ask` |
   | 決済画面へ進んだ数 | `premium:checkout` |
   | 支払い完了 | `premium:paid`（合計）・`premium:paid:solo`・`premium:paid:duo` |

   どこで落ちているかを見て、無料の量・コピー・プランの数を1つずつ試す。
4. **LINEスタンプを申請する**: 人の手で描いたキャラが完成したら、いちばん出ているタイプから申請する。
5. **B2Bの営業資料を作る**: 診断完了が10万を超えたら、実績の数字を入れて作る。悪口診断のように、配信・動画での利用を自由にするプレスキットも用意する。
