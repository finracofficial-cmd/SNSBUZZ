# 月100万円を安定して稼ぐための計画

このメモは、ポンコツ図鑑で**手取り月100万円**を、バズ頼みではなく毎月出すための計画。数字のうち実測でないものには「推定」と書いている。公開したら、推定の数字を `#/admin` の実測に置きかえて読み直す。

## 結論

1. 売上は「**1日の診断の完了 × 完了1回あたりの売上**」で決まる。推定の基本値（購入率0.6%・単価430円・広告とアフィリエイトあり）では、完了1回あたり約3.7円。月100万円には**1日 約9,000回**の完了が要る。
2. 完了1回あたりの売上を上げる施策（価格テスト・ふたりの相性・完全版・決済をやめた人への答え）と、流入を増やす施策（紹介ループ・シール・今週のお題）で、**1日 約4,000〜6,000回**まで下げる。
3. 「安定」は、売上の柱を**流入しだいの柱**（完全版・広告・アフィリエイト）と**流入に左右されにくい柱**（タイアップ・ライセンス・スタンプ）に分けて作る。目安は流入しだい70万円・左右されにくい30万円。

## 売上の式

```
月の手取り ＝ 30日 × 1日の完了 × 完了1回あたりの売上 ＋ タイアップ・スタンプなど
完了1回あたりの売上 ＝ 購入率 × 単価 × (1 − 手数料3.6%)
                    ＋ (1 − 購入率) × 1人あたりのページ数 × 広告の収益(1ページ)
                    ＋ アフィリエイト(1人)
```

広告は完全版を買った人には出さないので、買った人の分は引いている。`#/admin` の「月100万円までの試算」が、この式をそのまま使う（初期値は直近7日の実測）。

| 項目 | 推定の基本値 | どこで実測を見るか |
|---|---|---|
| 購入率（かんたん診断の完了あたり） | 0.6%（くわしい診断に進む25%×その中の2.4%） | `#/admin` の売上表・試算 |
| 単価 | 430円（じぶん用390円・ふたり用590円が2割） | 売上表の「平均単価」 |
| 1人あたりのページ数 | 6 | AdSense の管理画面 |
| 広告の収益 | 1,000ページあたり150円（パーソナライズしない広告なので低めに置く） | AdSense の管理画面 |
| アフィリエイト | 1,000人あたり300円 | Amazon アソシエイトの管理画面・`aff:*` のクリック数 |

## シナリオ（すべて推定）

| シナリオ | 購入率・単価 | タイアップなど | 完了1回あたり | 月100万円に必要な1日の完了 | 月の購入件数 |
|---|---|---|---|---|---|
| 完全版だけ（広告なし） | 0.6%・430円 | 0円 | 2.5円 | 約13,400回 | 約2,400件 |
| 基本 | 0.6%・430円 | 0円 | 3.7円 | 約9,100回 | 約1,600件 |
| 基本＋タイアップ月1件 | 0.6%・430円 | 30万円 | 3.7円 | 約6,300回 | 約1,100件 |
| 改善 | 1.0%・470円 | 0円 | 5.7円 | 約5,800回 | 約1,700件 |
| 改善＋タイアップ月1件 | 1.0%・470円 | 30万円 | 5.7円 | 約4,100回 | 約1,200件 |
| 改善＋タイアップ＋スタンプ・グッズ | 1.0%・470円 | 35万円 | 5.7円 | 約3,800回 | 約1,100件 |

- 「改善」は、下の施策で購入率を0.6%→1.0%、単価を430円→470円（価格テストで490円が勝つか、ふたり用・ふたりの相性・完全版が伸びた場合）にした値。
- いちばん不確かなのは購入率。0.3%なら必要な完了は約1.5倍、1.5%なら約半分になる。公開後2週間の実測で、この表を引き直す。
- 参考：1日9,000回の完了は月27万回。`docs/monetization.md` の試算（月30万回で約83万円）とほぼ同じ規模。

## 安定させるための柱の分け方

| 柱 | 目安（月） | 流入への依存 | 状態 |
|---|---|---|---|
| 完全版（じぶん用・ふたり用・ふたりの相性・完全版） | 50万円 | 大 | 実装済み。販売開始は設定しだい |
| 広告（AdSense・パーソナライズしない） | 12万円 | 大 | 実装済み。審査が通ったら ID を入れる |
| アフィリエイト（タイプ別のおすすめ） | 3万円 | 大 | 実装済み。トラッキングID を入れる |
| タイアップ・オリジナル診断の制作 | 30万円（月1件） | 小 | 窓口 `#/biz` を実装済み。営業は人がやる |
| LINEスタンプ・グッズ・ライセンス | 5万円 | 小 | スタンプの画像は `npm run stamps` で書き出せる。申請は人がやる |

流入はバズのあと急に落ちる（`docs/monetization.md` の前提）。流入に左右されにくい柱が30万円あれば、流入が半分になった月でも、手取りは約65万円残る。逆に、タイアップは「月の完了が10万回を超えた実績」がないと取りにくいので、**最初の3か月は流入の柱を伸ばすことに集中**し、実績の数字ができてから営業を始める。

## 実装した施策と、効くところ

| 施策 | 効くところ | どこで効き目を見るか |
|---|---|---|
| 売上の記録と目標ダッシュボード（`#/admin`） | すべて。毎日のペースと、目標までの1日あたりの件数がわかる | 売上表・試算 |
| **ふたりの相性・完全版**（相性ページのモザイク＋購入案内） | 購入率。相性は友達と見るので、買う理由が増える | `paywall:pair` と支払い完了 |
| **価格テスト**（`PREMIUM_PRICE_ALT`。週ごとに390円⇔490円） | 単価。表示1回あたりの売上でくらべる。同じ週はだれにでも同じ価格 | A/Bテストの `price` |
| **決済をやめた人への答え**（迷った理由を1回だけ聞く） | 購入率。理由が「高い」「払い方」「おうちの人」に分かれるので、次に直すところもわかる | ファネルの「迷った理由」 |
| おうちの人に払ってもらう | 購入率（カードを持たない10代） | `paywall:ask` |
| **紹介ループ**（自分のリンクから友達3人で虹色カード） | 流入。シェアする理由を1つ増やす。虹色カード自体もシェアされる | シェアの表の「紹介で初めて診断した友達」 |
| 広告・アフィリエイト（購入者には出さない） | 買わない99%の人からの売上 | 各サービスの管理画面 |
| 法人・学校の方へ（`#/biz`） | タイアップ・ライセンスの問い合わせ | `out:biz` |
| LINEスタンプの書き出し（`npm run stamps`） | 流入に左右されにくい売上と、トーク画面での宣伝 | Creators Market の管理画面 |
| A/Bテスト（購入案内の文言・自動表示・計算中） | 購入率・シェア率 | A/Bテストの表 |

## 人がやること（設定のチェックリスト）

販売・広告は、設定を入れるまで動かない。上から順に。

1. **特定商取引法の表記**：`site/assets/config.js` の `seller` を本物にして、環境変数 `SELLER_READY=1`。
2. **Stripe**
   - 390円の価格を作り `STRIPE_PRICE_ID`、`STRIPE_SECRET_KEY`、`PREMIUM_SECRET`（長いランダム文字列）、Webhook の `STRIPE_WEBHOOK_SECRET`。
   - ふたり用：590円の価格を作り `STRIPE_PRICE_ID_DUO`。
   - 価格テスト：490円の価格を作り `STRIPE_PRICE_ID_ALT` と `PREMIUM_PRICE_ALT=490`。最低4週（各案2週）続けて、`#/admin` の判定が出てから決める。決めたら、勝った価格を `STRIPE_PRICE_ID`・`PREMIUM_PRICE` に入れ、ALT の2つを消す。
   - PayPay：Stripe で有効にしてから `STRIPE_PAYMENT_METHODS=card,paypay`。
3. **D1**：`schema.sql` をもう一度流す（`refs` の表が増えた。`CREATE TABLE IF NOT EXISTS` なので、何度流しても大丈夫）。
4. **KPI**：`KPI_TOKEN` を入れて、`#/admin` で見る。
5. **広告**：AdSense の審査に出す。通ったら `config.js` の `ads.client` と `ads.slots` を入れる（`ads.txt` はビルドで自動で作られる）。
6. **アフィリエイト**：Amazon アソシエイトのトラッキングID を `affiliate.amazonTag` に入れる。
7. **外のお店と窓口**：`links.stamps`（LINEスタンプ）・`links.goods`（グッズ）・`links.lineOfficial`（LINE公式アカウント）・`links.bizContact`（法人の問い合わせ。メールアドレスかフォームのURL）。
8. **LINEスタンプ**：`npm run content && npm run stamps` で `stamps/` に40個＋メイン＋タブを書き出し、中身を ZIP にして Creators Market に申請する。セリフは `scripts/stamps.mjs` の `STAMPS` で変えられる。

## 毎週の運用

| いつ | やること |
|---|---|
| 毎日（5分） | `#/admin` の「このペースだと今月は」と「目標まで（1日あたり）」を見る。日別のグラフで、完了が前の週の同じ曜日より落ちていないか見る |
| 毎日 | TikTok・Instagram に1〜2本。`npm run cards` のタイプ紹介スライドと結果画像の見本を、20タイプで順番に回す。コメントで多いタイプを次の日に出す |
| 月曜 | 今週のお題が自動で切りかわる。お題のスクリーンショットを投稿する。価格テスト中は、価格もこの時刻に切りかわる |
| 月曜 | 先週の数字を1行で記録する（完了・購入率・単価・シェア率・紹介の数・迷った理由の多いもの） |
| 月に1回 | A/Bテストの判定を見る。判定が出たものは負けた案を消して、次の実験を入れる。迷った理由のいちばん多いものに合わせて、購入案内の文言かプランを1つ直す |
| 月に1回 | タイアップの問い合わせに返事をする。実績の数字（完了数・シェア数）を `#/biz` の説明と営業資料に入れなおす |

## 判断のルール

- **月の半ばでペースが目標の70%未満**：完了が足りないのか、完了1回あたりが足りないのかを試算で分ける。完了が足りなければ投稿を増やし、1回あたりが足りなければ購入案内（文言・無料の量）を1つ試す。
- **購入率が0.3%未満のまま2週間**：無料の量（15%・30%・45%）のテストに入る。迷った理由が「中身がわからない」に偏っていたら、第1章の見本を増やす。
- **完了が前の週の半分以下**：バズが終わった合図。新しい隠しタイプやシーズンの企画（季節の二つ名など）を用意して、次の山を作る。それまでは流入に左右されにくい柱（タイアップ・スタンプ）の準備を進める。
- **返金・チャージバックが売上の2%を超えた**：購入の確認画面と、おうちの人の同意の流れを見直す。

## 守ること（攻めすぎない）

- 価格テストは週ごとにして、同じ週はだれにでも同じ価格にする。特定商取引法の表記に「週ごとに変わることがある」と書く。二重価格（「通常〇〇円→390円」）は使わない。
- 決済をやめた人に割引はしない（やめると安くなると覚えられると、買う人までやめるようになる）。迷った理由を聞くのは1回だけ・3日に1回まで。
- タイアップは必ずPR表記をつける（ステルスマーケティング規制）。10代に向かない商材は受けない。結果や回答を宣伝の対象選びに使わせない。
- 広告はパーソナライズしない。結果ボタン・シェアボタンの近くに置かない。完全版を買った人には出さない。
- 紹介のごほうびは見た目だけ（虹色カード）。完全版の中身を紹介で開けられるようにはしない（買った人との不公平を作らない）。
